# Как показать КР №4 на защите

Работа: «СветДом», чистый JavaScript. Шкабара Иван Владимирович, ЭФБО-01-25.

## Что сказать в начале

«Я взял адаптивный магазин из КР №3 и создал отдельный репозиторий `kr4-js-shop`. HTML задаёт структуру страницы, CSS — внешний вид и адаптивность, а JavaScript — поведение. Теперь карточки создаются из массива, работают поиск, фильтры, сортировка, проверка форм, корзина и избранное. Фреймворков в этой версии нет».

## Показ за 5–7 минут

1. Открыть репозиторий и README. Показать шесть HTML-страниц, CSS и папку `js`. В `data.js` показать восемь товаров: четыре модели и четыре LED-комплекта.
2. Открыть каталог. В HTML контейнер `[data-products]` пустой: карточки добавляет `createProductCard` из `catalog.js`. Показать `document.createElement`, `textContent`, `classList.add`, `append`.
3. В поиске написать `лайм`: остаются две позиции. Дополнительно выбрать категорию «Классическая»: результат пуст. Сбросить фильтры. Это показывает, что условия работают одновременно.
4. Выбрать «Классическая», «Только в наличии», «Сначала дороже». Показать три оставшиеся позиции в порядке убывания цены. В коде показать `[...products]`, `filter` и `sort`.
5. Добавить сердечко, включить «Только избранное». Перезагрузить страницу: отметка сохраняется. Включать фильтр после перезагрузки нужно снова; сохраняется сам список избранного.
6. Два раза добавить «Лайм» и один раз «Классику». Открыть корзину: 12 970 ₽. Нажать `+`, затем `−`, удалить позицию. Показать `cart`, `getCartTotal` с `reduce` и `localStorage`. Перезагрузить: корзина сохраняется.
7. Перейти к заявке: состав корзины виден в форме. Пустая отправка показывает ошибки. Неверный e-mail и короткий телефон тоже не проходят. Исправить поля и поставить согласие: появляется сообщение о подготовке заявки. Объяснить, что сервер не подключён и реального заказа нет.
8. Показать модальное окно доставки на главной, закрыть через Escape. В `modal.js` показать `showModal`, `close` и возврат фокуса.
9. Показать Console без ошибок. В режиме устройств проверить мобильный каталог и меню. В контактах сохранены исходные отзывы.

Лучше заранее открыть вкладки с каталогом, корзиной, заявкой и кодом. Чтобы начать с пустой корзины, нажмите «Очистить корзину». Избранное очищается повторным нажатием на сердечки. Не очищайте все данные браузера на защите.

Если GitHub Pages ещё не включён, запустите `python -m http.server 8000` из папки проекта и откройте `http://localhost:8000/`. Не закрывайте терминал с сервером. `ERR_CONNECTION_REFUSED` на localhost означает, что локальный сервер не запущен или выбран другой порт.

## 22 вопроса преподавателя

### 1. Что хранится в data.js?

Массив `products` из восьми объектов, названия категорий и небольшие общие функции. Объект товара содержит `id`, `title`, `category`, числовую `price`, логическое `isAvailable`, `image`, `description` и `isLedKit`.

### 2. Почему товары — массив объектов?

Массив хранит список, объект — свойства одной позиции. Можно пройти по списку, отфильтровать, отсортировать и найти товар по id. Одни данные используются в каталоге, корзине, заявке и подробностях товара.

### 3. Почему у товаров одинаковые свойства?

Одна функция `createProductCard(product)` должна работать с любым товаром. Если вместо `price` у одного объекта будет другое имя, карточка и расчёт суммы получат неправильное значение.

### 4. Как работает поиск?

Событие `input` вызывает `renderCatalog`. `trim()` убирает пробелы по краям. Запрос и название приводятся к нижнему регистру. `includes()` проверяет вхождение запроса в название. После каждого ввода перерисовывается список.

### 5. Как работает категория?

Из `select` читается `value`. Если значение `all`, подходят все категории. Иначе остаются товары, у которых `product.category === category`. Значения в данных и HTML совпадают: `work`, `classic`, `decor`.

### 6. Как работает сортировка по цене?

`result.sort((a, b) => a.price - b.price)` сравнивает две цены. Отрицательное число ставит `a` раньше `b`: дешевле сначала. Для дорогих сначала используется `b.price - a.price`. Цены — числа, поэтому не возникает строкового порядка вроде «100 перед 20».

### 7. Зачем копировать массив перед sort()?

`sort()` меняет тот массив, на котором вызван. `[...products]` создаёт новый массив. Если сортировать `products` напрямую, исходный порядок потеряется. В нашем коде он сохраняется, поэтому можно выбрать «Исходный порядок».

### 8. Что такое DOM?

Представление HTML-документа как дерева объектов в браузере. JavaScript может найти узел, изменить его текст и классы, добавить или удалить элементы. У нас так появляются карточки и ошибки формы.

### 9. Что делает querySelector()?

Находит первый элемент по CSS-селектору. Например, `document.querySelector('#search')` находит поле поиска, а `document.querySelector('[data-products]')` — контейнер карточек. Если элемента нет, вернётся `null`; это нужно учитывать на других страницах.

### 10. Что делает createElement()?

`document.createElement('article')` создаёт элемент в памяти. Он появится на странице после добавления через `append`. Наш помощник `createElement` вызывает этот метод, назначает классы и текст.

### 11. Почему используется textContent?

Он записывает обычный текст, не выполняя HTML. Например, введённое имя с `<img ...>` останется строкой. Мы применяем это к названиям, сообщениям, ошибкам и результату формы.

### 12. Чем опасен innerHTML?

Он разбирает строку как HTML. Если туда попадёт непроверенный пользовательский ввод, злоумышленник может внедрить разметку с опасными обработчиками. В прикладных скриптах этого проекта `innerHTML` не используется.

### 13. Что такое classList?

Интерфейс для работы с CSS-классами элемента: `add`, `remove`, `toggle`. Например, `stock.classList.toggle('stock--unavailable', !product.isAvailable)` включает оформление отсутствующего товара. Это назначает стиль, не переписывая все классы строкой.

### 14. Для чего data-*?

Пользовательские HTML-атрибуты для связи разметки с поведением. `data-action="add-to-cart"` говорит, какое действие выполнить, `data-product-id="1"` — с каким товаром. В JavaScript это `button.dataset.action` и `button.dataset.productId`. Значение из атрибута — строка, id переводится через `Number()`.

### 15. Что такое событие?

Сообщение браузера о действии: `click` — нажатие, `input` — изменение ввода, `change` — изменение выбора, `submit` — попытка отправить форму, `reset` — сброс. Обработчик реагирует на событие.

### 16. Почему addEventListener()?

Он привязывает функцию к событию отдельно от HTML, позволяет нескольким обработчикам работать на одном элементе и сохраняет читаемую структуру. Например, поле поиска не содержит `oninput`; его поведение описано в `initCatalog`.

### 17. Что такое делегирование событий?

Событие от кнопки всплывает к родительским элементам. Один обработчик `click` на документе находит кнопку через `event.target.closest('button[data-action]')`. Он обслуживает все карточки, даже созданные заново после фильтрации. Не нужно назначать обработчик каждой новой кнопке.

### 18. Для чего preventDefault()?

Отменяет стандартное действие браузера. В обработчике `submit` мы отменяем закрытие формы через `method="dialog"` и показываем собственные ошибки или результат. Он не останавливает всплытие события — для этого есть другой метод.

### 19. Как работает валидация?

`initValidation` собирает поля и создаёт сообщения ошибок. При `submit` вызывается `getFieldError` для каждого поля: обязательность, имя, e-mail, телефон, товар, дата и согласие. `showFieldError` выводит ошибку рядом с полем и меняет `aria-invalid`. При ошибках фокус ставится на первое неверное поле. При успехе показывается подготовленная заявка; данные никуда не отправляются.

### 20. Почему ошибки на странице, а не alert()?

Рядом с полем понятно, что исправлять. Можно видеть все ошибки сразу и продолжать заполнение, не закрывая всплывающее окно. `aria-describedby` связывает поле с подсказкой для экранного диктора. У нас нет `alert()` как способа уведомления.

### 21. Какие самостоятельные доработки?

Корзина с количеством, удалением и очисткой; расчёт через `reduce`; сохранение корзины и избранного в `localStorage`; фильтры избранного и наличия; счётчики; отключённые кнопки отсутствующих товаров; карточки LED-комплектов; динамические страницы всех восьми товаров; понятные пустые состояния; расширенная проверка и сброс форм; окно доставки с управлением фокусом. Сценарии описаны в README и проверяются автотестом.

### 22. Почему копирование методички не даёт максимум?

По условиям базовая часть оценивается максимум в 4 из 8 баллов. Для повышенного уровня нужны осмысленные доработки и умение объяснить реализацию. Корзина, сохранение, избранное и связанный сценарий заказа расширяют базовое задание; итоговую оценку выставляет преподаватель на защите.

## Ещё несколько важных различий

- `const` запрещает переназначить переменную, но не запрещает менять содержимое массива; `let` нужен для переменной, которой присваиваем новый массив.
- `filter` возвращает новый массив подходящих элементов; `find` — один объект или `undefined`; `map` — новый массив преобразованных значений; `reduce` — одно итоговое значение.
- В корзине хранятся только id и количество. Цена находится по id в `products`. Нельзя доверять цене, записанной пользователем в хранилище.
- `localStorage` хранит строки. `JSON.stringify` превращает массив в строку, `JSON.parse` — обратно. `try/catch` перехватывает ошибки чтения и записи. Перед использованием проверяется структура данных.
- HTML `placeholder` — только пример ввода; значение не подставляется и маску телефона не создаёт.
- Скрытие фильтров работает через `<details>/<summary>`; прилипание — через CSS `position: sticky` с 1024 px. JavaScript отвечает за применение фильтров к товарам.
- Форма проверяется на клиенте. Настоящий сервер должен самостоятельно проверять и данные пользователя, и цены. Корзина в браузере не является серверным заказом.
- `docs/verification.json` хранит результаты теста. Сайт не читает этот файл; его можно открыть в репозитории для проверки, но он не нужен для работы магазина.
