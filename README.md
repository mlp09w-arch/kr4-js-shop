# СветДом — КР №4: JavaScript

**Шкабара Иван Владимирович, ЭФБО-01-25.**

Интерактивная версия магазина настольных ламп на чистом JavaScript: DOM, события, массивы, формы и безопасный вывод данных. Проект выполнен в отдельном репозитории на основе [КР №3](https://github.com/mlp09w-arch/kr3-responsive-shop), исходный коммит `7e121ba`. Оформление, фотографии, адаптивные сетки, отзывы и прижатый к низу футер сохранены. Bootstrap и другие фреймворки в этой работе не используются.

[Сайт](https://mlp09w-arch.github.io/kr4-js-shop/) · [Репозиторий](https://github.com/mlp09w-arch/kr4-js-shop) · [Подготовка к защите](DEFENSE.md)

## Страницы и запуск

- `index.html` — главная, четыре карточки из общего массива, условия доставки в модальном окне.
- `catalog.html` — все товары, поиск, фильтры и сортировка.
- `product.html?id=1` — подробности выбранного товара; без параметра показывается «Лайм».
- `cart.html` — товары, количество, удаление и общая сумма.
- `order.html` — подготовка заявки на корзину или одну выбранную лампу.
- `contacts.html` — контакты, проверка сообщения и исходные отзывы Анны и Михаила.

Для работы сайта не нужны сборка и установка npm-пакетов. Из папки проекта:

```bash
python -m http.server 8000
```

Затем открыть **http://localhost:8000/**. Терминал с сервером должен оставаться открытым. `localhost` — адрес вашего компьютера, преподавателю нужно давать ссылку GitHub Pages или запускать сайт на его компьютере отдельно.

HTML можно открыть двойным щелчком, но для одинаковой работы `localStorage` между страницами рекомендуется HTTP-сервер. После изменения файлов обновите страницу. Без JavaScript показаны пояснение и статические разделы сайта; интерактивный каталог требует JS.

## Данные и методы массивов

В `data.js` восемь объектов с одинаковыми полями:

- `id` — уникальное число;
- `title` — название;
- `category` — `work`, `classic` или `decor`, совпадает с `value` фильтра;
- `price` — число в рублях;
- `isAvailable` — логическое значение наличия;
- `image` — имя файла без расширения;
- `description` — описание;
- `isNew` — новая ли это модель.

Восемь разных моделей: Лайм, Классика, Нуар, Лесная птица, Кристалл, Графит, Лесной уют и Банкир. Для новых моделей используются четыре фотографии пользователя. Удалённые комплекты имели id 5–8; новым лампам присвоены id 9–12, поэтому сохранённая корзина не подменит старую позицию другой моделью. Две позиции помечены как отсутствующие: кнопки покупки отключены, фильтр наличия их исключает.

`filter` отбирает подходящие товары; `sort` меняет порядок копии; `find` ищет один товар по id; `some` проверяет наличие; `forEach` создаёт элементы; `map` составляет описание заявки; `reduce` суммирует количество и стоимость; `slice` выбирает четыре товара для главной.

## Каталог: как это работает

В HTML нет вручную прописанных карточек каталога. `querySelector('[data-products]')` находит контейнер. `createProductCard` создаёт карточку через `document.createElement`, назначает классы через `classList`, записывает текст через `textContent` и добавляет дочерние узлы через `append`. Перед новым выводом `replaceChildren()` удаляет старые карточки.

1. Событие `input` на поиске вызывает `renderCatalog`. Запрос обрезается через `trim()`, переводится в нижний регистр, название проверяется через `includes()`.
2. Событие `change` реагирует на категорию, сортировку и наличие.
3. Все ограничения объединяются через `&&`: поиск не отменяет выбранную категорию.
4. Используется копия `[...products]`. Цена по возрастанию: `a.price - b.price`; по убыванию: `b.price - a.price`; название: `localeCompare(..., 'ru')`.
5. Обновляются карточки и число найденных товаров. При нуле показываются сообщение и кнопка сброса. Сброс возвращает все восемь позиций.

Событие `reset` возникает до сброса значений браузером. Поэтому перерисовка запланирована через `requestAnimationFrame` после стандартного действия сброса.

## Самостоятельные доработки

### Корзина и сумма

Кнопка содержит `data-action="add-to-cart"` и `data-product-id`. Один обработчик `click` на документе находит нажатую кнопку через `closest()`. Это **делегирование событий**: оно работает и для карточек, созданных после поиска.

Корзина — массив `{ productId, quantity }`. Повторное добавление увеличивает количество. Можно изменить его от 1 до 99, удалить позицию или очистить корзину. На всех страницах обновляется счётчик общего количества, а не только числа разных моделей. После перерисовки корзины фокус возвращается на доступный элемент.

```js
cart.reduce((sum, item) => {
  const product = products.find((product) => product.id === item.productId);
  return sum + product.price * item.quantity;
}, 0);
```

Например: две лампы «Лайм» и одна «Классика» → `3490 × 2 + 5990 = 12970 ₽`. Доставка не включена, стоимость нужно уточнять отдельно.

### Сохранение корзины

Корзина сохраняется под ключом `svetdom-kr4-cart`. Для записи используется `JSON.stringify`, для чтения — `JSON.parse` внутри `try/catch`.

Восстановление проверяет массив, известные id, доступность товара и целое количество 1–99; дубликаты и неподходящие записи отбрасываются. Цена из `localStorage` не принимается: она берётся из `products`. При ошибке доступа или повреждённом JSON сайт продолжает работу и показывает сообщение. Если хранение заблокировано, состояние текущей страницы остаётся в памяти, но может сброситься при переходе или перезагрузке. Изменения другой вкладки применятся после перезагрузки.

### Понятные состояния

Добавлены отсутствие товара, бейджи новых моделей, число найденных товаров, счётчики корзины, подтверждения действий, пустые состояния с переходом к выбору ламп. На странице товара неизвестный id показывает «Товар не найден», а не ошибку скрипта.

## Формы и проверка

Форма заявки принимает всю корзину или одну выбранную лампу в количестве 1. Состав и стоимость видны до проверки. `submit` обрабатывается через `addEventListener`, `preventDefault()` отменяет стандартное действие формы. Ошибки не выводятся через `alert()`.

Проверяются:

- обязательные значения после `trim()`;
- имя от двух символов;
- e-mail: непустые части до и после `@`, точка в домене и отсутствие пробелов;
- телефон: от 10 до 15 цифр, допустимы пробелы, скобки, дефисы и один плюс в начале;
- существующий товар в наличии или непустая корзина;
- дата не раньше сегодняшней, если указана;
- сообщение в контактах — от 10 до 1000 символов;
- согласие на обработку данных.

У поля есть текст ошибки, `aria-invalid` и `aria-describedby`. После неудачной отправки фокус ставится на первое ошибочное поле; исправление сразу обновляет его ошибку. Сброс очищает значения, ошибки и результат.

После корректного заполнения показывается **подготовка заявки**, а не настоящая отправка. Сервер приёма и оплата не реализованы. Данные формы не сохраняются в `localStorage` и не отправляются по сети. В исходном HTML для формы сохранена немодальная обёртка `dialog open` и `method="dialog"`: если JS выключен, ввод не уходит в URL или на сервер. При включённом JS стандартное закрытие отменяется через `preventDefault`, результат выводится на той же странице.

Клиентская валидация улучшает удобство, но при подключении настоящего сервера данные потребуется проверять и на сервере.

## Безопасный вывод и доступность

В прикладных скриптах нет `innerHTML`, `eval` и inline-обработчиков `onclick`. Пользовательский ввод и восстановленное состояние не превращаются в HTML. Текст `<img ...>` в имени будет показан как текст. Пути картинок и ссылки строятся из проверенных записей массива, а не из ввода пользователя. Персональные данные не сохраняются.

У элементов есть подписи, видимый фокус, сообщения `role="status"`, доступные названия кнопок корзины. Модальное окно поддерживает Escape и возврат фокуса. Таблица на узком экране становится карточками строк, с 640 px возвращается табличный вид; искусственного `min-width: 640px` нет.

Адаптивность из КР №3 сохранена: до 640 px карточки в один столбец; с 640 px — в два; с 768 px — парные поля формы и двухколоночная корзина; с 1024 px — меню для компьютера и прилипающие фильтры. В каталоге на большом экране остаются два столбца рядом с фильтром. Футер удерживается внизу короткой страницы через flex и минимальную высоту `body`.

## Проверка перед сдачей

[verification.json](docs/verification.json) — технический результат автоматических проверок в локальном Chromium. Это не настройки сайта, не Lighthouse и не подменённый отчёт с опубликованного адреса.

Проверки выполняются скриптом [tests/browser.mjs](tests/browser.mjs). Для них установите Node.js и запустите `npm install`. Откройте локальный сервер на порту 8000 и выполните `npm test` в другом терминале.

Нужен установленный Chrome/Chromium. Скрипт ищет стандартный Linux-путь `/usr/bin/chromium`; на другом компьютере задайте `BROWSER_PATH` с путём к браузеру. `BASE_URL` позволяет сменить адрес локального сервера. Для просмотра самого сайта npm не требуется.

Ручной сценарий:

1. Каталог: восемь товаров. Поиск `лайм` → один результат, категория «Классическая» вместе с ним → пустой результат. Сброс → восемь.
2. Выбрать «Классическая», «Только в наличии», «Сначала дороже» → Кристалл, Классика.
3. Добавить два «Лайма» и одну «Классику». Корзина показывает 12 970 ₽. Изменить количество, удалить позицию, проверить сумму и счётчик.
4. Перезагрузить корзину. Товары сохраняются. Перейти к заявке и проверить состав.
5. Отправить пустую форму → ошибки. Ввести неверные email и телефон → ошибки. Исправить → сообщение о подготовке. Сбросить → результат и ошибки очищены.
6. Открыть контакты, проверить форму и наличие обоих отзывов.
7. Открыть доставку на главной, закрыть кнопкой и Escape.
8. Проверить ширины 360, 768, 1024 и 1440 px; страницы не имеют общего горизонтального скролла. В Console на всех шести страницах нет ошибок.

Автотесты также проверяют повреждённый JSON, недоступный `localStorage`, подмену цены, неизвестные id и безопасный текстовый вывод.
